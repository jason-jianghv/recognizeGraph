## 1. 总体架构（先定这个，再写代码）

```text
App（拍照/相册）
  → HTTPS 上传图片 + category(animal|plant|transport)
  → 自有后端 Recognize API
       → 用 API Key/Secret 换 access_token（缓存）
       → 按 category 调百度对应接口
       → 映射为统一 candidates[]
  → App 结果页横滑 → 详情页
```

**必须有后端的原因**：密钥不能下发；`access_token` 需服务端缓存刷新；便于限流、日志、儿童内容过滤。

## 3. 百度接口与产品分类映射

| App 分类 | 百度接口 | 关键参数 | 用途 |
|----------|----------|----------|------|
| 动物 | `/rest/2.0/image-classify/v1/animal` | `top_num=5`，`baike_num=5` | 结果页多候选 + 百科简介 |
| 植物 | `/rest/2.0/image-classify/v1/plant` | 同上 | 同上 |
| 交通工具与建筑 | `/rest/2.0/image-classify/v2/advanced_general`（通用物体和场景） | 取 Top N | 建筑、场景、一般交通工具 |

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 交通/建筑不如动植物准 | 通用接口 + 车型兜底；难例收集后考虑 VL 兜底 |
| 免费额度不够 | 控制台看套餐；开发用压缩图、缓存同图 hash |
| Key 泄露 | 轮换密钥；Git 扫描；仅 CI/服务器注入 |
| Clash SOCKS 导致 httpx 报缺 socksio / 识别失败 | 已装 `httpx[socks]`；百度请求用 `trust_env=False` 直连 |
| 百科文案不适龄 | MVP 截断展示；下期 LLM 改写或自建文案 |
